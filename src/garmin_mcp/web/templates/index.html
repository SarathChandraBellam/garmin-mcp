How it works

Three steps, about two minutes. You need no password and no database, and nobody else holds your key.

1

Create a key

Create a Personal API key in Garmin Connect. You choose how long it lasts and can revoke it at any time.

2

Add the server

Point your MCP client at /mcp and send your key in the X-Garmin-Api-Key header.

3

Ask away

"How did I sleep this week?" "Compare my resting HR to last month." Each call fetches live from Garmin.

Get your Garmin Personal API key

Garmin offers a self-serve Personal API, so you can read your own health and activity data with a key you create.

  1. Sign in to Garmin Connect on the web with the account that your watch syncs to.
  2. Open Settings → Personal API Key.
  3. Click Create Key, read and accept Garmin's Personal API terms, and choose an expiry: 30, 90, 180 or 365 days.
  4. Copy the key now. Garmin shows it only once. Store it in a password manager.
  5. Put the key in an environment variable such as GARMIN_API_KEY and add the server to your client (below).

Good to know

  • Treat the key like a password. Anyone who has it can read your Garmin data.
  • To revoke the key, open the same settings page. It stops working at once.
  • When the key expires, create a new one and update your client config.
  • Some metrics, such as Training Readiness and Training Status, are not in the Personal API.

Connect your client

Every request carries your key in X-Garmin-Api-Key (or Authorization: Bearer <key>). Any client that can send a custom header works.

claude mcp add --transport http garmin $mcp_url \
  --header "X-Garmin-Api-Key: <your key>"

Add this to ~/.cursor/mcp.json:

{
  "mcpServers": {
    "garmin": {
      "url": "$mcp_url",
      "headers": { "X-Garmin-Api-Key": "${env:GARMIN_API_KEY}" }
    }
  }
}

Add this to .vscode/mcp.json. VS Code asks for the key once and stores it securely:

{
  "inputs": [
    { "type": "promptString", "id": "garmin-key", "description": "Garmin Personal API key", "password": true }
  ],
  "servers": {
    "garmin": {
      "type": "http",
      "url": "$mcp_url",
      "headers": { "X-Garmin-Api-Key": "${input:garmin-key}" }
    }
  }
}

Add this to claude_desktop_config.json. It uses mcp-remote to send the header:

{
  "mcpServers": {
    "garmin": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "$mcp_url",
               "--header", "X-Garmin-Api-Key:${GARMIN_API_KEY}"],
      "env": { "GARMIN_API_KEY": "<your key>" }
    }
  }
}

Claude.ai on the web and mobile can't send custom headers, so it can't connect yet.

Tools

All tools are read-only. Dates are YYYY-MM-DD, or pass a period such as last_7d, last_30d, this_month or ytd. Send X-Timezone: Europe/Berlin (or a timezone argument) so “today” is your day. Coordinates and owner profile fields are removed from the output.

Privacy and security

Stores nothing

There is no database. Your key stays in your client's config and arrives with each request. The server uses it for that request and then forgets it.

Your key, your data

The deployment holds no keys of its own. Each client sends its own key, so it can only read its own owner's data. Headers are never logged.

Official API only

The server uses Garmin's Personal API. It does not ask for your password and does not scrape data.
